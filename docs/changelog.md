# Changelog

All notable changes to bxvtt are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The release version (`SERVER_VERSION` and workspace `package.json` versions, reported by `GET /api/health`) covers the HTTP `/api` and WebSocket `/ws` protocol in `@bxvtt/shared/protocol`, the `@bxvtt/shared/client` TypeScript SDK, server environment variables, and the web client. `SCHEMA_VERSION` (`5` in `apps/server/src/db.ts`) versions the SQLite schema in `.data/bxvtt.db`, which the server migrates forward automatically at startup, whereas `bxapi` (the loopback HTTP rules server) and `osrlib` (its B/X rules engine) version game rules and save documents separately.

## [0.2.0] - 2026-11-22

### Added

- **Article-free item labels (`@bxvtt/shared/text`):** Added `itemLabel(noun, quantity)` to format inventory rows, wizard review lists, item pickers, and cache contents without leading indefinite articles (`Chainmail`, `Leather armour`, `Shield`, `Mace`, `6 torches`, `7 standard rations`, `Waterskin`, `Potion`) while keeping `itemPhrase` for mid-sentence narration.
- **Automated GitHub Pages documentation publishing (`.github/workflows/docs.yml`):** Added the `Docs` GitHub Actions workflow and configured Docusaurus `baseUrl: '/bxvtt/'` to build and deploy `website/` to <https://mmacy.github.io/bxvtt/> on `main` documentation changes, published releases, and manual `workflow_dispatch` runs.

### Changed

- **UI microcopy, control labels, and accessible names (`@bxvtt/web`, `@bxvtt/server`, `@bxvtt/shared/text`):** Rewrote user-facing copy, button and menu labels, dialog prompts, empty states, error messages, command and field descriptions, rule rejection templates, and event narration across the client, server, and shared text package. Removed backend service names (`bxapi`, `the rules engine`) from normal gameplay and character creation flows, standardized rejoin and server-host terminology, updated `StoredSheet` shield and ring slot badges to `Worn`, and updated E2E screenshot and `/kit` sample parties to class-matched character names (`Flarg`, `Doke`, `Tinks`, `Elfy`, `Clarence`, `Mazpar`, and `Huge`).

### Fixed

- **Referee picker, map tooltip, and condition formatting:** Replaced raw `snake_case` class, spell-list, category, and dropped-pile item identifiers in referee pickers and map tooltips with formatted B/X labels, normalized `'paralyzed'` to `'paralysed'` in `conditionLabel`, and gave the referee panel's active encounter and battle card a distinct ARIA region name so it never collides with the main stage's `Encounter` region.

## [0.1.0] - 2026-11-22

### Added

- **Multiplayer server and SQLite store (`@bxvtt/server`):** Fastify serves 66 HTTP endpoints under `/api` and real-time state updates over `/ws`, calling `bxapi` over loopback HTTP for all rules execution. The server stores users, tables, 100-bit Crockford Base32 invite codes, member roles (`referee` and `player`), lobby rosters, character seats (linking party members to players), caller assignments (designating who speaks for the party), feed entries, notes, map annotations, monster target handles, pending battle declarations, and `bxapi` cleanup queues in SQLite (`node:sqlite`, schema version 5). State-changing game requests enforce `expected_revision` optimistic concurrency (`409 revision_conflict`) and `Idempotency-Key` replay safety, errors return RFC 9457 `application/problem+json` documents with stable `code` strings, and the server reports full `bxapi` client quotas via `507 bxapi_storage_full` while logging warnings past 80% usage. See [Architecture](architecture.md).
- **Role-based projections and command authorization:** Every HTTP response and WebSocket broadcast (`snapshot`, `game`, `feed`, `annotations`, `notes`, and `rejoin_requests`) filters state per recipient on the server, omitting `RefereeState`, referee-visibility events, full adventure JSON, referee notes, unmapped-level annotations, and secret rolls from player payloads. The server derives `game.scene` strictly from `osrlib` party knowledge (`explored` cells, entered areas, found, sprung, or removed traps, found tricks, and resolved encounters) and issues persistent 96-bit `tgt_` target handles for visible monsters so players never receive internal `bxapi` monster IDs or unrevealed lair hoards. Before forwarding a command to `bxapi`, the server classifies its JSON command schema into member, party, referee, or battle-resolution permissions and verifies the sender's role and seat. In the browser, referees can toggle the **Referee lens** (`Shift+L`) to render the player projection locally when also playing a character.
- **Browser identity, tunnel sharing, and returning-player rejoin:** Users authenticate with origin-scoped 256-bit `bxt_` bearer tokens stored as SHA-256 digests on the server. Running `npm run share` publishes `127.0.0.1` over a public HTTPS Cloudflare quick tunnel (`cloudflared`) with an automatic 144-bit `BXVTT_HOST_KEY` and `BXVTT_PUBLIC_ORIGINS` allowlist while `bxapi` remains private on loopback. When a tunnel URL or browser changes, `/api/rejoin/*` runs a referee-approved rejoin flow using a 256-bit polling secret, a 30-second claim window, automatic cancellation when the visitor leaves, and 90-day `token_retired` tracking to restore the player's existing identity, characters, and seats. See [Play over the internet](getting-started/share-online.md).
- **Transport, input, and rate-limit hardening:** Token buckets throttle requests per IPv4 address, IPv6 `/64` prefix, and authenticated user alongside per-user and per-table resource quotas. The server enforces 64 KiB JSON body limits (8 MiB for adventure uploads), rejects prototype-pollution keys and deep JSON nesting (past depth 64), rejects ASCII/Unicode control characters and bidirectional overrides in display strings, caps WebSocket client frames at 16 KiB, requires WebSocket `Origin` matches and authentication within 10 seconds, and sends strict HTTP security headers (`Content-Security-Policy` with `script-src 'self'`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`, and proxy-aware `Strict-Transport-Security`). See [Security and trust model](hosting/security.md).
- **Protocol schemas, TypeScript SDK, and event prose (`@bxvtt/shared`):** Zod v4 schemas in `@bxvtt/shared/protocol` validate every HTTP request, response, RFC 9457 problem code, and WebSocket message, paired with OpenAPI-generated `bxapi` types in `@bxvtt/shared/bxapi` (`npm run gen:bxapi`). `@bxvtt/shared/client` exports `BxvttClient` and `TableConnection` with typed methods for all 66 endpoints, automatic heartbeats, exponential-backoff WebSocket reconnection, and `feed_after` sequence catch-up, while `@bxvtt/shared/text` formats `osrlib` game events and rule rejections into B/X table prose. See [HTTP API, WebSocket, and SDK](reference/http-and-websocket.md).
- **Character wizard, character sheets, and lobby setup (`@bxvtt/web`):** A six-step wizard guides character creation across all seven B/X classes (cleric, dwarf, elf, fighter, halfling, magic-user, and thief), including 3d6 ability rolls, prime-requisite adjustments, alignment and bonus languages, arcane starting spells, and equipment shops with class kits validated non-destructively via `POST /api/characters/check`. Character sheet drawers display B/X combat stats, encumbrance, conditions, light controls, item transfers and drops, spell memorization, spell-book learning, and out-of-battle spellcasting. The lobby provides marching-order arrangement, seat and caller assignment, invite rotation, and controls for all 13 `osrlib` optional rules.
- **Town services and canvas dungeon map:** Five town tabs cover the outfitter (with multi-character carts and dungeon-readiness reminders), temple services (`cure_light_wounds` through `raise_dead` paid from pooled party gold), gem and jewellery sales, resting (one turn, a night, or a full day), and spell preparation. In dungeons, a custom HTML5 canvas renderer draws explored 10-foot cells under fog of war in three themes (blueprint, torchlit, and parchment) with zoom, pan, and party-follow camera controls, a minimap, contextual door, trap, treasure, and stair actions, a distance ruler, player-colored pings, freehand strokes, numbered note pins, and keyboard cell-cursor navigation with screen-reader announcements.
- **Encounters, simultaneous battle rounds, and combat playback:** Encounter controls support parley, waiting, evasion (with coin or food distractions), turning undead, item hand-offs, and engaging battle. During battle, `PUT /api/tables/{t}/game/declarations/{member_id}` coordinates simultaneous per-character declarations across seats with live shared status, conservative rank- and equipment-aware quick actions, gaze-defense choices, and automatic or manual `resolve_battle_round` resolution. When `bxapi` refuses a round, the server attributes nameless rejections to the offending character via non-advancing `bxapi` probes without clearing declarations. Accepted rounds play back beat by beat and conclude with aftermath loot cards or victory and game-over summaries.
- **Feed, quest journal, shared notes, and B/X rules compendium:** The chronological table feed combines Markdown chat, multi-recipient and referee whispers, `bxapi`-backed `/roll` slash commands and dice-tray rolls (including secret referee rolls), and narrated game events with unread dividers, category filters, text search, and backward pagination. The three-tab journal tracks active and completed quests, dated chronicle entries, and auto-saving 50,000-character shared party notes with optimistic conflict resolution (`Keep mine`, `Take theirs`, or `See both`). The built-in rules compendium provides faceted search across classes, spells, monsters, equipment, magic items (behind a player spoiler gate), languages, reference tables, actions, and the Open Game License 1.0a notice from gzip-compressed, `ETag`-cached `/api/catalogs/*` bundles.
- **Referee workspace and campaign saves:** An eight-tab referee panel (`Now`, `Act`, `Story`, `Key`, `Roll`, `Log`, `Notes`, and `All`) provides live room keys, peaceful encounter resolution, quest, flag, and trigger controls, post-teleport trigger prompts, stateless `bxapi` generators (treasure types A-V, monsters, room stocking, and NPC parties) with seed replay, full referee event logs, private notes, and schema-driven forms for all 23 `bxapi` referee commands. Tables store up to 100 manual saves plus the 10 newest milestone autosaves, support `.bxsave.json` exports, and restore saved sessions from mid-game, end screens, or the lobby (`Continue from a save`) with automatic seat remapping.
- **Bundled adventures, authoring builder, and automated verifier (`adventures/`):** Every server offers two original `osrlib` modules compiled from `adventures/src/*.mjs` (*The Drowned Bell*, a 3-level, 36-area campaign dungeon, and *The Toll at Crookback Bridge*, a 1-level, 13-area single-session module) alongside `bxapi`'s built-in *The Barrow of the Forgotten King*, plus per-table custom `.json` upload validation (up to 8 MiB) and live `adventures/` directory scanning. Zero-dependency scripts in `adventures/tools/` provide an ASCII grid compiler (`LevelBuilder` in `build.mjs`) and an automated static and live `bxapi` verifier (`check.mjs`) that checks schema validity, entrance reachability, level transitions, keyed encounters, triggers, and quests. See [Included and custom adventures](adventures/included-adventures.md) and [Author and validate adventures](adventures/authoring-and-checking.md).
- **Design system, verification suites, and documentation site:** `@bxvtt/web` builds on a token-driven UI kit (`apps/web/src/ui`, with component galleries at `/kit` and `/kit/table`) using Radix UI primitives, self-hosted Fraunces, Atkinson Hyperlegible Next, and Rokkitt variable fonts, custom B/X class, equipment, and die SVGs, full keyboard navigation, code-split client bundles, and in-memory Brotli and gzip asset serving. Automated checks cover TypeScript, ESLint, Prettier, Vitest unit and live-`bxapi` server integration suites (including scans ensuring player responses never include referee data), multi-browser Playwright end-to-end game and `axe-core` accessibility suites (`e2e/`), GitHub Actions CI against production bundles, and a Docusaurus 3.10 documentation site (`website/` and `docs/`) with light and dark torch-ember themes.
