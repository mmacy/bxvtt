# Changelog

All notable changes to bxvtt are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The release version (the root `package.json` version, which the server reads at startup and the web build reads at build time, and which `GET /api/health` reports) covers the HTTP `/api` and WebSocket `/ws` protocol in `@bxvtt/shared/protocol`, the `@bxvtt/shared/client` TypeScript SDK, server environment variables, and the web client. `SCHEMA_VERSION` (`7` in `apps/server/src/db.ts`) versions the SQLite schema in `.data/bxvtt.db`, which the server migrates forward automatically at startup, whereas `bxapi` (the loopback HTTP rules server) and `osrlib` (its B/X rules engine) version game rules and save documents separately.

## [Unreleased]

This release needs a `bxapi` built on `osrlib` 2.8, which is `bxapi` `main` from its pull request 58 onward. Update and restart `bxapi` before you start this version. With an older engine, the server serves no game: it refuses every game request and WebSocket snapshot with the new `503 bxapi_outdated` problem code, and `GET /api/health` reports `degraded` with the versions for a signed-in user. Without the check, an older `bxapi` would leave the player view without the item names, emptied caches, room trap states, and caches in reach that the client reads, the battle board unable to check declarations, and `bxapi` accepting a player's out-of-battle spell or item aimed at a creature the party hasn't met. With a `bxapi` older than pull request 51, the character wizard's checks also fail.

### Added

- **Leave and delete a table from the table menu (`@bxvtt/web`):** The lobby header has a new **Table menu**, and the play screen's table menu gains **Delete table** for referees. Every member can **Leave table** from either screen. The leave dialog says when leaving also deletes the table, and it tells the only referee of a table with other members to make another member a referee or delete the table. When a referee deletes a table, the other connected members return to their table list, where a notice names the table and who deleted it.
- **Sign out and delete profile (`@bxvtt/web`, `@bxvtt/server`, `@bxvtt/shared/client`):** The profile menu has **Sign out** and **Delete profile**, backed by `POST /api/users/me/sign-out` and `DELETE /api/users/me` (`BxvttClient.signOut` and `BxvttClient.deleteMe`). Signing out invalidates the token on the server, and the dialog lists the tables the person can come back to through the rejoin flow. Deleting a profile takes the user out of every table as leaving does, deletes their stored characters, and keeps what they wrote in shared tables under "A former member". Other tabs in the same browser follow a sign-out, a deletion, or a new sign-in.
- **Hit point and starting gold rolls in the character wizard (`@bxvtt/web`, `@bxvtt/server`, `@bxvtt/shared/protocol`):** The wizard has a seventh step, **Hit points and gold**, where the player rolls each and sees the dice `bxapi` rolled. Rolling hit points fixes the class and the first-level reroll option for those ability scores, so a roll can't be made again by going back or reloading. New routes `GET /api/ability-rolls/{roll_id}/starting-rolls`, `POST /api/ability-rolls/{roll_id}/hit-points`, and `POST /api/ability-rolls/{roll_id}/gold` read and make the rolls, and new problem codes `ability_roll_locked`, `hit_points_not_rolled`, and `gold_not_rolled` refuse a request that would reveal a roll the player hasn't made.
- **Combat playback controls (`@bxvtt/web`):** The playback strip has pause and resume (`K`), step back (`,`), step forward (`.`), and four speeds, next to skip (`Esc`). The viewer's speed is saved in their preferences. Playback is local to each viewer, so pausing holds up nobody else.
- **Documentation link and version on every screen (`@bxvtt/web`):** Every screen shows a **Docs** link to <https://mmacy.github.io/bxvtt/> and the bxvtt version in its bottom left corner. The version is the root `package.json` version, written into the client at build time.
- **Hover help in the design kit (`apps/web/src/ui`):** `Button`, `IconButton`, `LinkButton`, `ToolRailButton`, `ActionBarMenu`, `TabsTrigger`, and `SegmentedControl` options take a `tooltip`, and an icon-only control shows its label as its tooltip. A control with `disabled` and a `disabledReason` stays focusable, sets `aria-disabled`, and shows the reason on hover and on keyboard focus. Menu items, command palette actions, and list items show the reason under their label. `NumberInput` takes `minReason` and `maxReason`. An ESLint rule rejects the native `title` attribute on an interactive element.
- **`commandModesSentence` (`@bxvtt/shared/text`):** Builds a sentence that says when a command works from the `allowed_modes` in `bxapi`'s command catalog, such as "You can search only while exploring. The party is in town now."
- **`Banner` `announce` prop (`apps/web/src/ui`):** `announce` takes `alert`, `status`, or `none` and sets how a screen reader learns of a banner. A warning or danger `Banner` is still an alert by default. Pass `status` or `none` for a banner that appears each time a view opens, such as the battle composer's note that an action won't work.
- **Hide in battle (`@bxvtt/web`, `@bxvtt/shared/protocol`):** A character with thief skills has a **Hide** tab in the declaration composer, and a hiding character shows a **Hiding** badge on the battle board. The board never says whether a hide worked, because the referee's roll stays secret. A hiding thief can back-stab from outside the front rank, and the board says when a hide or a back-stab won't work. `DeclarationBody.action` accepts `hide`, a new `osrlib` 2.7 action, so a client author can declare it with `PUT /api/tables/{t}/game/declarations/{member_id}`.
- **Battle round preview (`@bxvtt/server`, `@bxvtt/web`, `@bxvtt/shared/protocol`):** The board shows why a declaration won't work before anyone resolves the round, and the range track marks where each character will stand after the declared moves. Whenever the server builds the declarations state with at least one stored declaration, it calls `bxapi`'s `POST /v1/sessions/{id}/battle-round/preview`. The new `DeclarationsState.projection` (`RoundProjection | null`) holds `advance_feet` by member and `front_rank` by group. A preview failure leaves `refusals` empty and `projection` `null`, and sets the new `DeclarationsState.preview_unavailable` to `true`, so a client can tell "nothing would be refused" from "the server couldn't check". The board then says "Actions can't be checked right now. If one won't work, you'll find out when the round resolves." and keeps **Resolve round** available.
- **`bxapi_outdated` problem code (`@bxvtt/shared/protocol`, `@bxvtt/server`, `@bxvtt/web`):** The server answers `503 bxapi_outdated` to a game request, and sends a WebSocket `error` with the same code, while `bxapi` runs an `osrlib` older than 2.8.0. `bxapi_unavailable` still means that the server can't reach `bxapi`. The home page shows a banner for an out-of-date game service, and a game request shows "The game service is out of date".
- **`save_unreadable` problem code (`@bxvtt/shared/protocol`, `@bxvtt/server`, `@bxvtt/web`):** `POST /api/tables/{t}/saves/{id}/restore` answers `502 save_unreadable`, where it answered `422 content_invalid`, when `bxapi` can't read a save because its rules engine was updated after the save was made. The dialog says to restore a newer save or start a new game.
- **Spells from the game's own catalog (`@bxvtt/server`, `@bxvtt/shared/protocol`, `@bxvtt/shared/client`):** `GET /api/tables/{t}/game/rules/spells/{spell_id}` (`BxvttClient.getSessionSpell`) returns `bxapi`'s `SpellTemplate` from the session's catalog to any member of the table, so a client can show the description, modes, and reversed form of a spell that the adventure bundles. It answers `404 not_found` for a spell that the player view doesn't name in `spell_names`, the same as for a spell that doesn't exist. `SpellId`, `SessionSpellParams`, and `SpellTemplate` are new in `@bxvtt/shared/protocol`.
- **Who can hide or back-stab, in the round projection (`@bxvtt/server`, `@bxvtt/shared/protocol`):** `RoundProjection.can_hide` and `RoundProjection.can_back_stab` list the declarers who could declare a hide or a back-stab beside the other stored declarations, from `bxapi`'s battle round preview. Offer the two actions from these lists when `DeclarationsState.projection` isn't `null`, and from `view.encounter.can_hide` and `view.encounter.can_back_stab` otherwise.
- **Plural item names on feed entries (`@bxvtt/server`, `@bxvtt/shared/protocol`, `@bxvtt/shared/text`):** `EntryNames.items_plural` records what to call two or more of each item that an entry's events name, from the player view's `item_names_plural`, so a line reads "2 vials of holy water". An entry stored before this release has none, and the text forms the plural itself. `TextContext.itemsPlural` and `extendContextWithNames(ctx, names, plurals)` carry the plurals in the text package.
- **Referee notes on adventure features (`adventures/`):** `osrlib` 2.8 adds `FeatureSpec.referee_notes`, text that the adventure's author writes for the referee alone. The player view never contains it, and the server sends it to referees inside the adventure document. The `feature()` helper in `adventures/tools/lib.mjs` passes it through, and thirteen caches in the two sample adventures use it for what a container holds, whose money it is, and how a trap is hidden. See [Author and validate adventures](adventures/authoring-and-checking.md#design-tips-for-multiplayer-fog-of-war).
- **The map's keyboard cursor announces what lies on a square (`@bxvtt/web`):** When you move the cursor with the arrow keys, a screen reader hears the treasure, dropped goods, other points of interest, and stairs, trapdoor, or chute on the square, in the words of the hover tooltip. Before, only a mouse user learned of a treasure.
- **Real ability dice in the character wizard (`@bxvtt/web`):** The roll step animates the three six-sided dice that `bxapi` rolled for each ability score, read from `rolls` on `POST /v1/ability-rolls` and `GET /v1/ability-rolls/{roll_id}`. The wizard used to pick three faces that added up to the score. A draft saved before this change keeps its choices, and the wizard fetches the dice again. While the dice load, the step shows three placeholder dice under the same header, and the dice then appear where they landed instead of rolling again.

### Changed

- **Combat playback pace (`@bxvtt/web`):** A beat now lasts between 1 and 3.5 seconds, by the length of its text, with a longer hold for a death, a spell, and the end of a battle. It lasted 420 to 700 ms before. The end screen waits for the final round's playback to finish, and for as long as a paused viewer stays paused.
- **Declaring in battle (`@bxvtt/web`):** Each character's row shows **Not declared yet** or the saved declaration with a **Change** button. The composer says that choosing an action declares it for the round. The footer counts the declarations for the round, names who is still to declare, and says what starts the round.
- **Ability trade step (`@bxvtt/web`, `@bxvtt/shared/text`):** A trade the player is still building shows guidance about the next step instead of "This ability trade isn't allowed". **Continue** stays enabled and, with a trade unfinished, says to finish the trade or reset it.
- **Hover help and disabled reasons across the client (`@bxvtt/web`):** Every screen's controls moved from the native `title` attribute to the kit's hover help, which also appears on keyboard focus. Disabled controls say why they're unavailable and what would make them available. The permission reasons name the action and the caller, such as "Only the caller can rest the party. Sam is the caller."
- **Character checks (`@bxvtt/server`):** `POST /api/characters/check` asks `bxapi` for one preview and returns only `valid` and `problem`. `gold_gp` is gone from the response. A check or a creation from an ability roll with purchases or equipped items is refused with `gold_not_rolled` until the player rolls the gold.
- **Per-user table limit (`@bxvtt/server`):** The limit of 50 now counts the tables a user created and still referees. A table that its creator hands to another referee and leaves no longer counts.
- **Monsters read by name, and players name them by ID (`@bxvtt/server`, `@bxvtt/web`, `@bxvtt/shared/text`, `@bxvtt/shared/protocol`):** Combat lines and feed entries read "Brenna hits Goblin 2" where they read "a goblin". A player now names a monster in `targets` or `target_id` by the ID that the `osrlib` 2.6 player view lists in `view.encounter.groups[].members`, and no longer by a `tgt_` handle. `creatureNames` in `@bxvtt/shared/text` (moved from `@bxvtt/shared/protocol`) numbers a label's creatures by ID, so a number doesn't change when a group splits, and a creature that is alone with its label reads by the label. `EntryLabel.name` in a feed entry's `names.monsters[id]` records the name, so an entry still reads "Goblin 2" after the fight. A disguised group stays disguised, and a referee's real NPC name wins.
- **`bxapi` checks a player's targets (`@bxvtt/server`, `@bxvtt/shared/protocol`):** `osrlib` 2.8 refuses a creature ID that the player view doesn't list with the same rejection as an ID that doesn't exist (`magic.cast.unknown_target`, `items.use.unknown_target`, or `battle.declaration.unknown_group`), so the server no longer checks targets itself. It forwards a player's commands and declarations as they are and sends `bxapi`'s rejections and preview refusals unchanged, where it used to answer a declaration with `422 target_unknown` and remove unlisted creature IDs from what players received. Every member of the table now receives the same declarations state. A referee's command at an unlisted creature gets the same refusal as a player's. `targets.test.ts` compares a player's answers for both kinds of ID in exploration, an open encounter, and a battle.
- **Stored declarations keep only `bxapi`'s fields (`@bxvtt/server`, `@bxvtt/shared/protocol`):** `DeclarationBody` lists the fields of `bxapi`'s `BattleDeclaration`, and the server drops any other field from a declaration before it stores it, because every member reads the stored declarations.
- **Declaration refusals come from the preview (`@bxvtt/server`, `@bxvtt/shared/protocol`):** `DeclarationsState.refusals` holds the preview's rejections, each with `member_id` taken from `params.character`, and it changes as members declare, where it used to hold only the rejections of the last refused resolve. A refused declaration stays stored, because another member's move can make it legal. Auto-resolve fires only when every declarer has declared and the preview refuses nothing, and the resolve controls say which characters need a different action. `fill_with_hold` declares `hold` only for characters who haven't declared and never replaces a stored declaration. A round that `bxapi` still refuses reports a rejection for each member in `params.character`, and a rejection of the whole round has `member_id: null`.
- **A group that runs stays a target until it escapes (`@bxvtt/web`):** A group that breaks and runs (`fleeing`) stays on the range track, marked as fleeing, and stays a target until it escapes the battle (`monster_escaped`).
- **Players see only the player view (`@bxvtt/server`, `@bxvtt/web`, `@bxvtt/shared/protocol`):** The `osrlib` 2.8 player view states everything the party perceives: entered `areas` with their names, descriptions, walked cells, and known room trap (`EnteredAreaView.trap_state`, `found` or `sprung`), visible `features` with opaque `feature:` handles, `trap_state`, and `emptied`, the caches in reach (`features_here`), known `transitions`, the `entrance`, `dungeons`, `can_travel_to_town`, and item names (`item_names` and `item_names_plural`). bxvtt no longer derives anything a player reads from the referee view, and `game.scene` is gone. A feed entry names items from the player views before and after the command and from an `item_identified` event. The web client works out what is at the party's cell with `partyHere(view)` and `useHere()`.
- **Treasure commands name a `feature:` handle (`@bxvtt/server`):** A player's `take_treasure`, `inspect_treasure`, or `remove_treasure_trap` must name a `feature:` handle from the player view or `pile`. Any other `feature_id` from a player is answered with `exploration.feature.unknown` without calling `bxapi`. The check stays because raw authored feature IDs still reach players in some events ([osrlib-python#322](https://github.com/mmacy/osrlib-python/issues/322)). A referee's tools send the same handles, from `RefereeState.feature_handles`. `osrlib` refuses a hidden or guessed cache with `exploration.feature.unknown` and an emptied one with `exploration.feature.emptied`, and answers `remove_treasure_trap` with `exploration.feature.unknown` whether the cache has no trap or an unfound one, where the server used to answer `exploration.trap.not_found`.
- **Transitions and traps say less (`@bxvtt/web`):** A stair, trapdoor, chute, or passage no longer says where it leads, and a known trap no longer states its trigger, because the player view doesn't state either.
- **Treasure cache descriptions reach players (`@bxvtt/server`, `adventures/`):** The `osrlib` 2.6 player view shows a treasure cache's authored `description` to the players once the cache is in sight, before anyone opens it and after it's emptied. **Referees who uploaded their own adventures: check every cache `description`.** A description that was safe because only the referee read it, such as one that lists the contents or describes a trap the party hasn't found, now reaches the table. Write each one as what the party sees from outside the container, and move what only the referee should read to the feature's new `referee_notes`. The sample adventures had their cache descriptions reworded this way. See [Author and validate adventures](adventures/authoring-and-checking.md#design-tips-for-multiplayer-fog-of-war).
- **Shorter, plainer interface text (`@bxvtt/web`, `@bxvtt/shared/text`, `@bxvtt/server`, `adventures/`):** A content design review changed what players read, so a client that quotes the old strings or a screenshot of them is out of date.
  - **Battle board:** A character whose action won't work gets a warning icon and **Won't work:** before the action, with the reason in the row, where the row showed a green check and **Declared:**. The footer says "Tinks needs a different action before the round can resolve.", and **Resolve now** and **Resolve round** say "Tinks needs a different action first." The composer drops its two explanatory lines, and the **Hide** tab says only that the character slips into the shadows to set up a back-stab. **Back-stab** reads "Strike a monster that hasn't noticed Tinks." and starts checked for a hiding thief, whose suggested action is **Back-stab** followed by the nearest monster group. The range track shows a faded portrait of each moving character in a dashed ring where it will stand, and reads "will move to 15 feet past the party line" for a screen reader. While a round plays back, the rows and the footer dim, but a player can still declare for the next round. A row returns to full opacity under the pointer or with focus inside it, and the **Hiding** badge waits for the beat where the character hides. Interface text says action, not declaration, and a group that leaves the battle is **Escaped**, where it was "Fled" or "got away". The board's collapse button reads **Collapse the battle board**, where **Hide** is now only the thief's action, and the referee's **Monsters** button says that it shows or collapses the monster roster and referee tools.
  - **Aftermath:** The card always offers the treasure the party can reach, as a row with its description and **Take treasure**. When the party found a trap on it, the row says "The party found a trap on this. Taking it may spring the trap." and the button reads **Take anyway**, where the card used to offer nothing until the trap was sprung or removed. Dropped goods read "Dropped goods lie here." with **Pick up**.
  - **Exploring:** A treasure row in the scene panel leads with its description, shows **Trapped**, **Trap sprung**, or **Trap disarmed** as a badge, and has a **Take** button and a **More for this treasure** menu (**Give all to one member**, **Check for traps**, **Disarm trap**), where every row had the same **Treasure** menu. The folded bar counts "1 thing here" or "3 things here", and the toggle reads **Collapse description** or **Show description**. Dropped goods have a **Pick up** button. Map tooltips say **Treasure** and **Emptied**, where they said "treasure cache" and "rolled treasure", and a referee's tooltip for a trap says **Springs on entry** or **Springs when opened**.
  - **Game text:** The refusals for a back-stab, a hide in the front rank, a staff of healing, and an unknown treasure or target are shorter and say what to do next. The back-stab refusal no longer says that surprise is the only way to back-stab, because a thief can also back-stab from hiding. An experience award that the one-level limit cut reads "Brenna gains 1,234 of the 2,000 experience points awarded." The problem message for `save_unreadable` says "The game was updated after this save was made".
  - **Sample adventures:** More sample cache descriptions describe only what the party sees.
- **Game text (`@bxvtt/shared/text`):** Coins read by denomination, so loot worth less than 1 gp reads as "39 copper pieces" where it read as nothing. An experience award reports what the character gained and says when the one-level limit cut it. New sentences cover hiding, a group that escapes, the potion and hand-over fizzles, and the new refusals. A declaration refusal names the member who declared, and a group that breaks and runs reads differently from one that escapes the battle.
- **Item names come from `osrlib` (`@bxvtt/shared/text`, `@bxvtt/server`):** Every item reads by `osrlib`'s display name, the same one the player view's `item_names` gives, so an item has one name in the feed and in the inventory. Seven names change, such as "hand mirror" where it read "steel mirror", and "50’ coil of rope". Item and monster plurals come from `bxapi`'s `display_name_plural` and `item_names_plural`. An item that nothing names reads "something", or "something else" beside named items, where it read as the words of its ID, which an adventure's author can make more revealing than the display name. `contextFromPlayerView` reads the view's `item_names` and `item_names_plural`, and `magicItemTemplateNoun(id)` is new.
- **Database schema (`@bxvtt/server`):** `SCHEMA_VERSION` is 7. Migration 7 drops the `target_handles` and `battle_refusals` tables, which bxvtt no longer uses, and deletes stored battle declarations, because one saved before the upgrade can hold a `tgt_` handle that the preview would refuse until its member declared again. The server migrates an existing database at startup. Version 6 added the `ability_rolls` columns that record the class and reroll option that the hit points were rolled with and when each roll was made.
- **One version for a release (`@bxvtt/server`):** `GET /api/health` reports the root `package.json` version, which the server reads at startup into `SERVER_VERSION`, instead of a hand-maintained copy of it. A release changes one file now, so the health check and the web client's footer always report the same version for a build. ([#32](https://github.com/mmacy/bxvtt/pull/32))

### Removed

- **Monster target handles (`@bxvtt/server`, `@bxvtt/shared/protocol`):** The server no longer mints `tgt_` handles. `scene.targets`, `SceneTarget`, `TargetHandle`, and the `target_handles` table are gone. A client names a monster by its ID in `view.encounter.groups[].members`.
- **The scene (`@bxvtt/server`, `@bxvtt/shared/protocol`):** `game.scene` is gone, with `packages/shared/src/protocol/scene.ts` and the types `Scene`, `SceneRoomTrap`, `SceneLevel`, `SceneArea`, `SceneTransition`, `SceneTrap`, `SceneCache`, `SceneFeature`, `SceneHere`, `ScenePosition`, and `TransitionLeads`. Read item names from the player view's `item_names` and `item_names_plural`, room traps from `explored[].areas[].trap_state`, emptied caches from `explored[].features[].emptied`, the caches in reach from `features_here`, and areas, features, transitions, the entrance, `dungeons`, and `can_travel_to_town` from the player view. A room trap no longer has a `removed` state, because `osrlib` never reports one.
- **The `target_unknown` problem code (`@bxvtt/server`, `@bxvtt/shared/protocol`):** A declaration aimed at a creature that the player view doesn't list is stored, and the preview refuses it with `bxapi`'s rejection.
- **Scene text helpers (`@bxvtt/shared/text`):** `extendContextWithScene` and `SceneNamesLike` are gone. `contextFromPlayerView` reads item names from the view.
- **Refusal probing (`@bxvtt/server`, `@bxvtt/shared/protocol`):** The sentinel probe, `DeclarationRefusal.candidates`, and the `battle_refusals` table are gone, because every rejection of a declaration now names its member in `params.character`.

### Fixed

- **Replay with reduced motion (`@bxvtt/web`):** **Replay** between rounds did nothing when reduced motion was on. It now starts paused, and the viewer steps through the round.
- **Explore action bar reasons (`@bxvtt/web`):** Search, Listen, Light, and Rest never showed why they were unavailable, because the reason went to a tooltip on a natively disabled button. They now stay focusable and show it.
- **Repeated death line in playback (`@bxvtt/web`):** A member who gained the dead condition and died in the same round appeared as two identical beats.
- **Documentation screenshot script (`docs/images/capture.mjs`):** The script waited on control labels that the 0.2.0 copy overhaul renamed, so it stopped at the lobby step. It now uses the current labels and sample party names, and every screenshot in `docs/images/` is regenerated. ([#33](https://github.com/mmacy/bxvtt/pull/33))
- **Turn undead for any turner (`@bxvtt/web`):** The **Turn undead** button was unavailable to a player whose cleric wasn't the first turner. It is now available when the viewer can act for any character who turns undead. ([#30](https://github.com/mmacy/bxvtt/issues/30))
- **Scroll spell targets on the inventory tab (`@bxvtt/web`):** A scroll's spell targets offered group IDs, which `osrlib` refuses. They now offer the party and the living creatures.
- **A result that arrived before the encounter panel opened never showed (`@bxvtt/web`):** The play shell loads lazily, and an encounter panel that mounted after a command's feed entry arrived treated the entry as history, so about one result in twenty never appeared. The store now records the newest feed entry at each mode change, and the panel plays back from there. ([#29](https://github.com/mmacy/bxvtt/issues/29))
- **Resolve round ignored an action that won't work (`@bxvtt/web`):** The action bar's **Resolve round** and the command palette's resolve action looked available and did nothing while an action wouldn't work. Both are now unavailable and say who needs a different action, like the board's button.
- **A hidden creature read as "null" in a refusal (`@bxvtt/server`, `@bxvtt/shared/text`):** The server replaced a creature ID that the player view doesn't list with `null` in a player's copy of a refusal, and the sentence read "null". The server now sends refusals as `bxapi` returns them, the text package treats a `null` param as missing, and two refusals gain a wording without a target.
- **Class names lost their capitals mid-sentence (`@bxvtt/shared/text`):** A class name keeps its capitals when it's a proper name, so a custom class reads "warlock of Sarn", not "warlock of sarn".
- **Text context flags (`@bxvtt/shared/text`):** A cloned text context dropped the referee's flags.
- **Turned undead detail (`@bxvtt/shared/text`):** The referee detail of a turn undead result showed a disguised monster's template ID.
- **Staff of healing refusal (`@bxvtt/shared/text`):** The refusal for a staff of healing aimed at a monster worded the monster as a party member.

## [0.2.0] - 2026-11-22

### Added

- **Article-free item labels (`@bxvtt/shared/text`):** Added `itemLabel(noun, quantity)` to format inventory rows, wizard review lists, item pickers, and cache contents without leading indefinite articles (`Chainmail`, `Leather armour`, `Shield`, `Mace`, `6 torches`, `7 standard rations`, `Waterskin`, `Potion`) while keeping `itemPhrase` for mid-sentence narration.
- **Automated GitHub Pages documentation publishing (`.github/workflows/docs.yml`):** Added the `Docs` GitHub Actions workflow and configured Docusaurus `baseUrl: '/bxvtt/'` to build and deploy `website/` to <https://mmacy.github.io/bxvtt/> on `main` documentation changes, published releases, and manual `workflow_dispatch` runs.

### Changed

- **UI microcopy, control labels, and accessible names (`@bxvtt/web`, `@bxvtt/server`, `@bxvtt/shared/text`):** Rewrote user-facing copy, button and menu labels, dialog prompts, empty states, error messages, command and field descriptions, rule rejection templates, and event narration across the client, server, and shared text package. ## [0.1.0] - 2026-11-22

### Added

- **Multiplayer server and SQLite store (`@bxvtt/server`):** Fastify serves 66 HTTP endpoints under `/api` and real-time state updates over `/ws`, calling `bxapi` over loopback HTTP for all rules execution. The server stores users, tables, 100-bit Crockford Base32 invite codes, member roles (`referee` and `player`), lobby rosters, character seats (linking party members to players), caller assignments (designating who speaks for the party), feed entries, notes, map annotations, monster target handles, pending battle declarations, and `bxapi` cleanup queues in SQLite (`node:sqlite`, schema version 5). State-changing game requests enforce `expected_revision` optimistic concurrency (`409 revision_conflict`) and `Idempotency-Key` replay safety, errors return RFC 9457 `application/problem+json` documents with stable `code` strings, and the server reports full `bxapi` client quotas via `507 bxapi_storage_full` while logging warnings past 80% usage. See [Architecture](architecture.md).
- **Role-based projections and command authorization:** Every HTTP response and WebSocket broadcast (`snapshot`, `game`, `feed`, `annotations`, `notes`, and `rejoin_requests`) filters state per recipient on the server, omitting `RefereeState`, referee-visibility events, full adventure JSON, referee notes, unmapped-level annotations, and secret rolls from player payloads. The server derives `game.scene` strictly from `osrlib` party knowledge (`explored` cells, entered areas, found, sprung, or removed traps, found tricks, and resolved encounters) and issues persistent 96-bit `tgt_` target handles for visible monsters so players never receive internal `bxapi` monster IDs or unrevealed lair hoards. Before forwarding a command to `bxapi`, the server classifies its JSON command schema into member, party, referee, or battle-resolution permissions and verifies the sender's role and seat. In the browser, referees can toggle the **Referee lens** (`Shift+L`) to render the player projection locally when also playing a character.
- **Browser identity, tunnel sharing, and returning-player rejoin:** Users authenticate with origin-scoped 256-bit `bxt_` bearer tokens stored as SHA-256 digests on the server. Running `npm run share` publishes `127.0.0.1` over a public HTTPS Cloudflare quick tunnel (`cloudflared`) with an automatic 144-bit `BXVTT_HOST_KEY` and `BXVTT_PUBLIC_ORIGINS` allowlist while `bxapi` remains private on loopback. When a tunnel URL or browser changes, `/api/rejoin/*` runs a referee-approved rejoin flow using a 256-bit polling secret, a 30-second claim window, automatic cancellation when the visitor leaves, and 90-day `token_retired` tracking to restore the player's existing identity, characters, and seats. See [Play over the internet](getting-started/share-online.md).
- **Transport, input, and rate-limit hardening:** Token buckets throttle requests per IPv4 address, IPv6 `/64` prefix, and authenticated user alongside per-user and per-table resource quotas. The server enforces 64 KiB JSON body limits (8 MiB for adventure uploads), rejects prototype-pollution keys and deep JSON nesting (past depth 64), rejects ASCII/Unicode control characters and bidirectional overrides in display strings, caps WebSocket client frames at 16 KiB, requires WebSocket `Origin` matches and authentication within 10 seconds, and sends strict HTTP security headers (`Content-Security-Policy` with `script-src 'self'`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`, and proxy-aware `Strict-Transport-Security`). See [Security and trust model](hosting/security.md).
- **Protocol schemas, TypeScript SDK, and event prose (`@bxvtt/shared`):** Zod v4 schemas in `@bxvtt/shared/protocol` validate every HTTP request, response, RFC 9457 problem code, and WebSocket message, paired with OpenAPI-generated `bxapi` types in `@bxvtt/shared/bxapi` (`npm run gen:bxapi`). `@bxvtt/shared/client` exports `BxvttClient` and `TableConnection` with typed methods for all 66 endpoints, automatic heartbeats, exponential-backoff WebSocket reconnection, and `feed_after` sequence catch-up, while `@bxvtt/shared/text` formats `osrlib` game events and rule rejections into B/X table prose. See [HTTP API, WebSocket, and SDK](reference/http-and-websocket.md).
- **Character wizard, character sheets, and lobby setup (`@bxvtt/web`):** A six-step wizard guides character creation across all seven B/X classes (cleric, dwarf, elf, fighter, halfling, magic-user, and thief), including 3d6 ability rolls, prime-requisite adjustments, alignment and bonus languages, arcane starting spells, and equipment shops with class kits validated non-destructively via `POST /api/characters/check`. Character sheet drawers display B/X combat stats, encumbrance, conditions, light controls, item transfers and drops, spell memorization, spell-book learning, and out-of-battle spellcasting. The lobby provides marching-order arrangement, seat and caller assignment, invite rotation, and controls for all 13 `osrlib` optional rules.
- **Town services and canvas dungeon map:** Five town tabs cover the outfitter (with multi-character carts and dungeon-readiness reminders), temple services (`cure_light_wounds` through `raise_dead` paid from pooled party gold), gem and jewellery sales, resting (one turn, a night, or a full day), and spell preparation. In dungeons, a custom HTML5 canvas renderer draws explored 10-foot cells under fog of war in three themes (blueprint, torchlit, and parchment) with zoom, pan, and party-follow camera controls, a minimap, contextual door, trap, treasure, and stair actions, a distance ruler, player-colored pings, freehand strokes, numbered note pins, and keyboard cell-cursor navigation with screen-reader announcements.
- **Encounters, simultaneous battle rounds, and combat playback:** Encounter controls support parley, waiting, evasion (with coin or food distractions), turning undead, item hand-offs, and engaging battle. During battle, `PUT /api/tables/{t}/game/declarations/{member_id}` coordinates simultaneous per-character declarations across seats with live shared status, conservative rank- and equipment-aware quick actions, gaze-defense choices, and automatic or manual `resolve_battle_round` resolution. When `bxapi` refuses a round, the server attributes nameless rejections to the offending character via non-advancing `bxapi` probes without clearing declarations. Accepted rounds play back beat by beat and conclude with aftermath loot cards or victory and game-over summaries.
- **Feed, quest journal, shared notes, and B/X rules compendium:** The chronological table feed combines Markdown chat, multi-recipient and referee whispers, `bxapi`-backed `/roll` slash commands and dice-tray rolls (including secret referee rolls), and narrated game events with unread dividers, category filters, text search, and backward pagination. The three-tab journal tracks active and completed quests, dated chronicle entries, and auto-saving 50,000-character shared party notes with optimistic conflict resolution (`Keep mine`, `Take theirs`, or `See both`). The built-in rules compendium provides faceted search across classes, spells, monsters, equipment, magic items (behind a player spoiler gate), languages, reference tables, actions, and the Open Game License 1.0a notice from gzip-compressed, `ETag`-cached `/api/catalogs/*` bundles.
- **Referee workspace and campaign saves:** An eight-tab referee panel (`Now`, `Act`, `Story`, `Key`, `Roll`, `Log`, `Notes`, and `All`) provides live room keys, peaceful encounter resolution, quest, flag, and trigger controls, post-teleport trigger prompts, stateless `bxapi` generators (treasure types A-V, monsters, room stocking, and NPC parties) with seed replay, full referee event logs, private notes, and schema-driven forms for all 23 `bxapi` referee commands. Tables store up to 100 manual saves plus the 10 newest milestone autosaves, support `.bxsave.json` exports, and restore saved sessions from mid-game, end screens, or the lobby (`Continue from a save`) with automatic seat remapping.
- **Bundled adventures, authoring builder, and automated verifier (`adventures/`):** Every server offers two original `osrlib` modules compiled from `adventures/src/*.mjs` (*The Drowned Bell*, a 3-level, 36-area campaign dungeon, and *The Toll at Crookback Bridge*, a 1-level, 13-area single-session module) alongside `bxapi`'s built-in *The Barrow of the Forgotten King*, plus per-table custom `.json` upload validation (up to 8 MiB) and live `adventures/` directory scanning. Zero-dependency scripts in `adventures/tools/` provide an ASCII grid compiler (`LevelBuilder` in `build.mjs`) and an automated static and live `bxapi` verifier (`check.mjs`) that checks schema validity, entrance reachability, level transitions, keyed encounters, triggers, and quests. See [Included and custom adventures](adventures/included-adventures.md) and [Author and validate adventures](adventures/authoring-and-checking.md).
- **Design system, verification suites, and documentation site:** `@bxvtt/web` builds on a token-driven UI kit (`apps/web/src/ui`, with component galleries at `/kit` and `/kit/table`) using Radix UI primitives, self-hosted Fraunces, Atkinson Hyperlegible Next, and Rokkitt variable fonts, custom B/X class, equipment, and die SVGs, full keyboard navigation, code-split client bundles, and in-memory Brotli and gzip asset serving. Automated checks cover TypeScript, ESLint, Prettier, Vitest unit and live-`bxapi` server integration suites (including scans ensuring player responses never include referee data), multi-browser Playwright end-to-end game and `axe-core` accessibility suites (`e2e/`), GitHub Actions CI against production bundles, and a Docusaurus 3.10 documentation site (`website/` and `docs/`) with light and dark torch-ember themes.
